# 科研工时复盘

私密 Sites 应用。`index.html` / `app.mjs` 是界面，`calc.mjs` 计算 R+E、积分和调休，`worker/index.mjs` 负责按已登录用户保存记录。

“休息日额外工作”把全部填写的工作时间按 1/4 计入调休，不套用工作日的任何扣分项；合理加班等符合条件的加分仍保留。旧记录在展示、周汇总和导出时按当前规则重新核算，原始记录不改写。

工作日使用调休时可选“主动调休”或“被动抵扣”。两类沿用相同余额、目标和积分规则；旧记录未标注时保留为“未标注”，周复盘给出对应时长。主动占比以本周全部实际使用时长为分母。个人工程指标只使用 E 时间：每日目标进度加 30 分钟、周目标 210 分钟，焦虑值取目标进度与累计 E 的正差；周一从零计算，不计入积分。

## 数据库

Sites 的 `DB` D1 绑定持久保存一张 `user_state` 表：

| 列 | 用途 |
| --- | --- |
| `user_id` | Sites 提供的已登录用户邮箱，主键 |
| `payload` | 该用户的每日记录、周复盘、规则与期初余额，JSON |
| `revision` | 每次修改递增，防止设备间静默覆盖 |
| `updated_at` | 最近写入时间 |

首次访问 API 时以 `CREATE TABLE IF NOT EXISTS` 初始化表。读写接口为同源的 `GET /api/state` 和 `PUT /api/state`；没有 Sites 用户身份时拒绝读写。客户端先读取云端，旧版浏览器数据只在云端为空时自动迁移；数据不一致时提供明确的选择，避免覆盖。保存失败保留本地缓存并提示未同步。

数据跨浏览器设备可用，但仍应定期使用“导出 JSON 备份”。数据库存储也不能承诺绝对零数据损失。

## 每周导出

在“一周复盘”中切换到目标周后，可以复制或下载 Markdown，也可以下载 JSON。导出只读取已经保存的当前周记录，不向服务器写入新数据；有未保存输入或同步冲突时先提示处理。文件名包含周一和周日日期。

JSON 使用 `research-time-weekly-export/v1` 格式：`week` 是日期与周复盘文字，`summary` 是当前规则重算的周汇总，`days` 固定七天；有记录的日期同时包含 `originalEntry` 和 `calculated`。`ruleSnapshot` 保留导出时的参数，`sourceSync` 指明云端同步状态。Markdown 只显示当前日状态下有效的字段，适合直接贴给 ChatGPT；下载后可手动添加到 ChatGPT Library。此功能不会改变站点的私密权限，也不自动写入 Library。

周导出还包含调休性质、按性质统计的时长和 E 工程指标的每日目标进度、累计时间与焦虑值。当前周的“周末焦虑值”根据已录入的整周 E 时间暂估，周日后才标为最终值；未来日期的每日焦虑值留空。

## 事务与压力管理

`events.mjs` 单独计算事件、推进链、每日压力峰值与历史残留；`events-ui.mjs` 提供首页概览、按所选日期回看事件、推荐与今日计划。R/E/P/S/C/M/A 只作为事件类别，事件压力不换算成工时，也不进入原积分、加班、调休或工程指标。压力等级 H0—H3 由用户决定，分类初值与期限、阻塞等提示只供参考。

事件卡片按日期显示已完成节点 → 当前进展，以及一个始终留空、不参加进展计算的“下一步行动”位置；每个已完成和当前节点旁直接显示各自的 H、状态和可协调性。事件信息窗口只设定初始节点和初始状态。独立的“新增／补录进展”窗口输入新的当前进展、实际发生日期及新节点的 H、状态、可协调性：每次保存都归档原当前节点，输入内容立即成为当前节点。没有新增节点的日期沿用上次进展；补录较早日期不会改写后续明确记录的节点文字。另用“更正节点状态”窗口选择初始、历史或当前节点修改其状态，且不新增进展。

事件在所选日期处于已结束状态时，链条末端标为“已结束”并保留最后进展文字，隐藏空白“下一步行动”和“新增／补录进展”；仍可查看和更正节点或编辑事件。按较早日期回看仍使用当日状态，重新开启后也不会反写已结束日期的展示。

事件卡片右上角仅显示类型与优先级。两者来自当前基础事件信息，因此编辑后在所选历史日期也同步更新；每个进展节点的 H、状态与可协调性仍按当时记录展示。

事件列表按所选日期收拢：显示当日未结束的事件、本周截至该日有发生或进展／状态记录的事件，以及当天仍计入前三天压力残留的事件。旧事件超过这段展示范围后只从列表隐藏，仍保存在数据库，可切换回历史日期查看；压力建模、周复盘与导出仍使用完整数据。

压力 `P_now` 是未结束事件当前节点 H 之和。每天保留各事件当日峰值 `qᵢ` 与日末压力 `pᵢ`；有连续前三天记录时，每个事件仅对相对今天已经下降的压力产生残留：`rᵢ = 0.5×max(0,qᵢ(昨日)−pᵢ(今日)) + 0.3×max(0,qᵢ(前日)−pᵢ(今日)) + 0.2×max(0,qᵢ(前三日)−pᵢ(今日))`；总残留 `D = min(6,Σrᵢ)`。同一事件持续 H3 时不会反复叠加残留；下降或结束后的压力仍会逐日衰减。按每日结束时的 H2/H3 计算连续高压天数，跨节点连续，降到 H1 或结束即清零；单个事件连续满 7 天增加 0.5、满 14 天增加 1 的持续负荷 `Cᵢ`，不因节点数多而加权。综合负荷 `L = P_now + D + ΣCᵢ`。历史不足时显示“记录不足”。这些都是观察量，不影响原工时、积分和调休。

新增事件可选实际发生日期，默认使用当前所选日期；`createdOn` 是事件开始参与压力计算的日期，`recordedAt` 保留真正录入时间。编辑时可以纠正发生日期。节点推进另有生效日期和真实录入时间：回看只使用该日及之前的进展快照，后续节点不会影响更早日期；补录和更正会重算周“事务负荷与恢复”。旧事件没有 `createdOn` 时使用原有 `createdAt`，旧工时和积分不受影响。

旧版曾允许通过普通编辑改写同一节点的“当前进展／下一步”，并在历史中留下不同的文字快照。回看时以该节点最后一次文字为准，在真正的“推进节点”处切换到下一个节点；各日期的压力、状态和可协调性仍取当日快照。这样更正发生日期后，旧文字不会在较早日期重新出现，也不会把后续节点提前显示。

推进或更正旧事件前会按进展节点对齐文字快照，再计算归档节点与后继节点。两个窗口保存期间分别禁用表单、显示同步提示并拦截重复提交。针对 2026-10-12 的“工程实践，搭建工位笔记本连接的流程打通和问题整合”，旧版两次输入若仍表现为一个完成节点加一条悬空的 `nextStep`，读取时会按原推进日期将其转换为两个完成节点和新的当前进展；原节点 ID 保留，修复只执行一次，并通过云端修订号同步。旧记录没有单独保存第一次输入的发生日期，因此修复只采用已有推进日期，不推测更早日期。

新增或编辑事件时只填写初始进展，不填写下一步行动或预计耗时。首次新增进展就归档初始节点，之后每次新增都立即更新当前节点。旧预计耗时保留在原始记录中，但不再用于计划压力建议或 Markdown 展示。

2026-10-15 针对受污染的“办理党员证明材料”旧记录，读写云端状态时移除该日期 16:21:56（中国时间）之前录入的同名事件及其计划引用；新录入的同名事件不会受影响。清理只触及事件与计划关联，不修改工时、积分、调休或其他事件。首次读取时使用数据库修订号写回，防止并发覆盖。

“现在怎么安排”给出每个未结束事件一次的有序列表：可执行的 P0／临期事项优先，临期但受阻的事项先协调或跟进，再安排 P1、普通可执行事项；在高负荷／疲劳时，非紧急高认知任务建议暂缓，非紧急受阻事项排在后面。相同类别按截止日期、优先级、节点 H、连续高压天数排序，逐项展示当前进展、依据和可采取的动作；按钮仍在这里加入或取消计划。“今日计划”保留原计划、当前选择和动态压力评估；精力状态可选。计划压力为 `L_plan = D + 所选事件 H 之和 + 所选事件持续负荷之和`，旁边展示全部事件的 `L`；选择变化立即重新评估。判断另参考自评精力、最近深夜工作、认知强度和等待状态。推荐不自动更改计划，也不加减积分。旧版手写计划调整继续保留在数据和周导出中。

云端仍使用同一张 `user_state` 表，在原 JSON 状态上增加 `events` 与 `eventDays`；旧记录会被保留。周导出在 `eventManagement` 中增加压力历史、周统计、事件及节点变化、参考推荐，逐日 `eventRecord` 保留精力、原计划、选择变化和计划压力。仅有事件记录的周也能导出。旧版备份不含新字段时，读取后补齐为空数组和对象。

## 检查与打包

```bash
node --test calc.test.mjs calendar.test.mjs worker.test.mjs weekly-export.test.mjs events.test.mjs
node build.mjs
```

输出包括 `dist/client/` 静态资源、`dist/server/index.js` Worker 和 `dist/.openai/hosting.json`。Sites 始终使用 `.openai/hosting.json` 中已有的项目 ID。
