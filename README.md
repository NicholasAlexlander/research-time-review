# 科研工时复盘

> 记录事实，辅助复盘，给工作与生活留出空间。

一个面向科研与个人工程实践的轻量记录工具：把每日投入、事件进展、积分调休和周复盘放在同一个页面，帮助理解时间花在哪里、事务如何推进，以及什么时候值得停下来休息。

**每日记录 · 链式进展 · 历史回看 · 计划建议 · 周复盘导出**

---

## ✨ 核心能力

| 模块 | 可以做什么 |
| --- | --- |
| 工时记录 | 按 R/E/P/S/C/M/A 分类填写时间，统计总投入与 R+E 有效任务 |
| 日期与休息 | 区分工作日、休息日、个人日期调整与休息日额外工作 |
| 积分与调休 | 展示积分明细、加班换算、调休累计和使用状态 |
| 事件进展 | 用连续节点记录任务推进，保留每个节点的压力、状态和可协调性 |
| 历史管理 | 补录遗漏进展、更正节点内容，按日期还原当时状态 |
| 计划与负荷 | 综合事件压力、近期残留和持续高压，辅助安排正式计划与候补任务 |
| 一周复盘 | 查看投入占比、产出、观察、调休性质和工程投入情况 |
| 数据导出 | 复制或下载 Markdown 周记录，导出 JSON 周记录与完整备份 |

## 🧭 从记录到复盘

1. **选择日期**：确认当天是工作、休息还是个人调整后的日期。
2. **填写事实**：记录各类时间、专项产出、阻塞以及观察／异常。
3. **推进事件**：新增当前进展，或补录历史日期遗漏的节点。
4. **安排当天**：从推荐中选择正式计划；只准备在空隙推进的事项可标为候补。
5. **回看一周**：检查时间结构、事务变化和休息使用情况，导出一份可长期保存的记录。

## ⏱️ 工时、积分与休息

### 时间分类

| 分类 | 含义 | 常见内容 |
| --- | --- | --- |
| R | 科研 | 调研、推导、实验、论文写作 |
| E | 工程 | 编码、构建、复现、脚本与个人项目 |
| P | 工作管理 | 计划、整理、复盘 |
| S | 自由创作 | 自主写作与创作实践 |
| C | 课程 | 上课、学习与课程作业 |
| M | 汇报沟通 | 组会、汇报与协作沟通 |
| A | 行政杂务 | 材料提交、审批与日常事务 |

**有效任务 = R + E**；其他分类仍计入总投入。页面按周展示各类投入和占比。

### 日期状态与调休

- 支持正常工作日、正常休息日、工作日调整为休息日、休息日调整为工作日，以及休息日额外工作。
- 日历结合已收录的中国法定节假日与调班安排；未收录年份按正常双休暂估并明确提示。
- 工作日最低目标默认 **7h**，使用已积累调休后按使用时长抵扣；普通加班由用户分段填写，超过 **8h** 时给出记录提醒。
- 休息日额外工作的全部工时计作加班，默认按 **1/4** 兑换调休，不触发工作日扣分。
- 使用调休可标记为 **主动调休** 或 **被动抵扣**。两者余额与目标抵扣方式相同，仅用于复盘，不额外加减积分。
- 整日调整为休息日与消费调休余额分开记录；工作日调整为休息日时展示明天计划。
- 积分按记录中的规则版本与配置核算，展示加分、扣分及每日明细；规则参数可在页面查看和调整。

## 🔗 事件与历史进展

一个事件可以持续多天，每个进展节点分别记录自己的描述、压力等级 **H0—H3**、状态和可协调性。

例如，一个通用工程任务可以这样推进：

**整理需求 → 搭建环境 → 验证功能 → 整理结果 → 已结束**

| 操作 | 行为 |
| --- | --- |
| 推进事件 | 新内容成为当前进展，原当前进展进入历史 |
| 补录进展 | 根据发生日期插入遗漏节点，同日可指定插入位置 |
| 更正节点 | 修改选定节点的描述或状态，不新增节点；文字更正保留前后内容与更正时间 |
| 历史回看 | 仅显示所选日期已经生效的进展，后续节点不会提前出现 |
| 自动归档 | 旧完成事件退出日常列表，原始记录仍保留 |
| 查询归档 | 按关键词或完成日期查找历史事件、查看链条和更正记录 |

生效时间与实际录入时间分别保存。日常列表保留未结束事件、本周有变化的事件，以及仍贡献压力残留的事件；归档只影响展示，不删除数据。

## 🌿 事务负荷与今日计划

压力指标用于观察事务安排，不是心理状态诊断，也不参与工时、积分或调休计算。

| 指标 | 含义 |
| --- | --- |
| 当前压力 P | 所选日期全部未结束事件的当前节点 H 之和 |
| 历史残留 D | 对前三天已下降的事件压力按 0.5 / 0.3 / 0.2 衰减，总值上限为 6 |
| 持续负荷 C | 单个事件连续 H2/H3 满 7 天增加 0.5，满 14 天增加 1；降压或结束后重算 |
| 综合负荷 L | P + D + C |

历史不足时显示“记录不足”，不会将未知数据直接当作零。节点补录和状态更正会按原模型重新计算受影响日期。

### 正式计划与候补任务

- **正式计划**：今天明确准备投入时间推进的事务。
- **候补任务**：只在等待间隙或有余力时考虑推进，不视为当天必须全部完成。
- 计划压力以正式计划的 H、对应持续负荷及历史残留为依据。
- 候补事件仍参与全部事务的 P、D、C 与整体负荷；标记候补不能隐藏整体压力。
- 推荐逐项列出事务、排序依据和可采取的动作，参考期限、优先级、阻塞状态、当前进展及精力情况；最终计划由用户选择。

## 📊 每周复盘与个人工程投入

周复盘汇总时间分布、R+E 有效任务、专项产出、积分、加班、调休与观察记录，并展示事件负荷变化。

调休统计区分本周使用总量、主动调休、被动抵扣、未标注记录及主动调休占比。

个人工程指标只使用 **E 类时间**：周目标默认 **3h30m**，每天目标进度增加 **30m**。

```text
工程焦虑值 = max(0, 本周已过去天数 × 30 分钟 − 本周累计 E 时间)
```

该数值只是工程投入的进度代理值：每周一重新计算，不结转、不形成欠债，也不加减积分。

### 导出与备份

- **Markdown**：适合阅读、归档或交给 ChatGPT 复盘，支持复制与下载。
- **周记录 JSON**：保留每日原始输入、计算结果、规则快照、事件进展、计划分类和压力统计。
- **完整 JSON 备份**：用于保存全部记录，并可通过页面导入恢复。
- 周文件名包含起止日期；导出不会自动公开记录，也不会自动上传到其他应用。

## 🔐 数据保存与访问

应用通过 **ChatGPT Sites** 托管，后端运行在 Cloudflare Workers，持久化记录保存在绑定的 D1 数据库中。

- 云端记录按登录用户区分；未认证的请求不能访问记录接口。
- 浏览器保留本地缓存，保存失败时提示待同步。
- 云端保存使用递增修订号检测冲突，避免设备间静默覆盖。
- **源码公开与记录公开相互独立**：本仓库提供应用代码，不包含使用者的云端日志；站点访问权限由部署配置单独控制。
- 建议定期下载完整 JSON 备份，特别是在迁移设备或部署环境之前。

## 🛠️ 技术架构

应用使用原生 HTML、CSS 和 JavaScript 模块，无前端框架依赖；计算逻辑与界面、存储接口分别组织。

| 文件 | 职责 |
| --- | --- |
| `index.html` / `style.css` | 页面结构、表单和样式 |
| `app.mjs` | 每日记录、周汇总、同步与备份交互 |
| `calc.mjs` / `calendar.mjs` | 工时积分调休核算与日期安排 |
| `events.mjs` / `events-ui.mjs` | 事件链、历史状态、压力计算和事件界面 |
| `plan.mjs` | 正式计划、候补任务与计划压力评估 |
| `weekly-export.mjs` | Markdown 与 JSON 周记录生成 |
| `worker/index.mjs` | 登录用户的记录读写与修订冲突检查 |
| `build.mjs` | 生成静态资源与 Worker 部署产物 |

持久化使用 `user_state` 表，包含用户标识、JSON 记录、修订号和更新时间；同源 `/api/state` 接口负责读取与保存。

### 检查与构建

使用支持内置 `node:sqlite` 的 Node.js 环境运行测试：

```bash
node --test calc.test.mjs calendar.test.mjs worker.test.mjs weekly-export.test.mjs events.test.mjs
node build.mjs
```

构建产物位于 `dist/client/` 和 `dist/server/`。部署时需要配置 Sites 身份认证和 D1 的 `DB` 绑定；单独打开 HTML 文件不能替代完整的云端服务。

> 设计原则：记录事实、辅助复盘、减少操作负担，让休息成为可主动选择的一部分。
